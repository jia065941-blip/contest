# 毁灭者提前结束固定复现

这个目录固定E06真实部署中的毁灭者2576和默认母巢51，用于复测飞行中途消失。场景只有两个实体，不注册红方策略和虫族策略，没有自爆虫，不计比赛成绩。原版引擎、原生模型和正式地图均未修改。

## 运行

在项目根目录使用Python 3.11.x，先按项目说明安装依赖。支持项目自带的Windows和Linux模型；本包已在Windows完成实测，Linux尚未实测。

```bash
python tools/repro_heavy_disappearance/run.py --output results/heavy_repro_01
```

默认执行原生模型与真实TrainingEnv两种复测。每次使用新的输出目录，防止覆盖已有记录。可用`--mode native`或`--mode engine`只运行其中一种。

## 固定输入与预期现象

- 毁灭者游戏位置为`(-62037.213996382685, 22181.174554022964, 3000)`米，母巢51位置为`(32921.742911, 4063.644775, 0)`米，沿用E06原始血量和类型。
- 原版转换得到毁灭者原生初始化高度约63804.49米；模型期望高度为30000米，包含原有10倍尺度。
- Windows参考结果：原生模型在64.65秒返回非负值。更新前迎角约80.02度，仍远离目标；真实引擎随后在第65步将其血量归零并设为不可见，母巢未受伤。
- 单体高度对照只将初始化高度改为30000米，目标、速度、载荷和模型不变，参考结束时间484.8秒。对照仅诊断输入高度的影响，不构成游戏修复。

`native_original.csv`和`native_height_control.csv`保存每次0.05秒原生更新；`summary.json`保留最后10次更新前后状态。`engine_trace.json`保存真实引擎逐步状态，`engine_events/`保存原有SDK事件。`attack_angle_deg`按模型使用的机体系速度计算，使用相同的57.3角度换算系数。

## 两种复测的含义

`native`使用`case.json`中冻结的原生初始化与目标输入，直接调用项目自带模型。后续坐标修复不会改变这一组输入，因此仍可研究原始高空输入为何触发退出。

`engine`加载标准格式的`scene.json`，通过公开部署接口部署，再运行未修改的TrainingEnv。它使用当前引擎转换；修复后的引擎可能不再出现第65步消失。请同时核对输出中的模型与转换文件哈希，不将未复现的结果自动解释为运行失败。

程序正常退出表示复测流程完成。是否复现应查看`angle_guard_observed`、`disappearance_step`及模型哈希。异常和缺失会直接报错，不自动重试。

## 版本与复现资料

原诊断基于`c81c7cd`，本目录加入的工程基准为`fce0476`。两者原生模型、坐标转换一致；`fce0476`仅删除毁灭者目标更新前的直接返回。复现不提交目标更新动作，因此这项变更不影响该案例。

`fixture_manifest.json`固定场景和输入文件哈希，并记录Windows与Linux模型及依赖库参考哈希。`reference_windows.json`为本目录在Windows执行两种复测后保存的小型核验摘要。原生模型存在迎角和侧滑角绝对值超过80度的退出判断；该样本实测触发迎角判断，外层引擎随后按飞行结束处理。

2026年11月7日在未修改的`fce04763fa7122bd2fedcb60c71bc4d8d53472ec`上实际执行默认复测命令：原生模型64.65秒退出，真实TrainingEnv第65步不可见、血量归零；母巢血量保持24。高度对照484.80秒结束。上述结果来自本目录脚本的实际运行。

## 原版红方策略与完整对局方法

`red_strategy.py`保留发生问题时的recovery入口，使用工程中的`user_agents/example/spatial`及`user_agents/example/common`实现。入口及共用实现与`c81c7cd`一致，未加入本地坐标修复或任务恢复修改。

在项目根目录执行：

```bash
python main.py --config tools/repro_heavy_disappearance/full_game.yaml
```

该配置固定E06、B8、种子42，态势每步保存，事件和动作全部保存。输出位于`results/heavy_repro_full_game`。这是原版策略的完整对局复测入口；本次新增实测验证的是上面的双实体案例，未重新运行整场E06。当前`pku`已允许毁灭者更新目标，完整策略发出的改目标动作可能改变消失时刻，因此不将第65步作为整场对局的固定断言。

快速检查消失问题使用第一条`run.py`命令；它无须运行整场比赛。诊断记录包含完整实体状态，不能作为选手策略的观测输入。
