# 竞赛场景

正式地图位于 `scenarios/`，共20张，默认场景为 `E01`。清单为 `scenarios/manifest.json`，版本为 `20261113_reduced_red_original_blue`，布局版本为 `local_xyz_m_20261103`。另有R01和Rtest练习场景。

|---|---|---:|---:|---:|---:|
|简单|E01—E06|15／24／85|4／7／10|78|40公里|
|中等|M01—M06|24／37／128|6／12／15|146|50公里|
|困难|H01—H08|40／66／214|8／20／20|348|60公里|

同一地图的三类红方共享连续部署矩形，可以自由选择每个单位的初始位置。正式地图的红方初始高度均为3000米，部署沿用初始高度，完成后全部出发。示例部署类可通过自身的 `plan_path` 使用网格数量方案。仿真步长为1000毫秒，单局最多3000步。天眼实体数量及引擎使用上限按小、中、大图分别为2、3、4，每次持续80步；当前R7空间策略按计划启用一次。

每张地图包含一个同名JSON和 `images/` 下的同名PNG：

- `E01.json` 等：模型配置、地图与部署区域、实体初态和时钟；可选 `metadata` 保存编号、标题、难度和说明；
- `images/E01.png` 等：人族部署区、虫巢布局、分类编号及探测范围的组织方信息图，包含暗巢位置。

`scenarios/manifest.json` 保存正式地图目录和发布文件哈希。自定义场景可直接通过 JSON 路径加载，无需登记清单或维护哈希。编辑字段与检查方式见 [格式说明](../FORMAT.md)。

图片宽6英寸，按300 dpi导出；英文与数字采用 Times New Roman，中文采用宋体（本次导出使用 FandolSong），字体与刻度均为10 pt。坐标为 `X (km)`、`Y (km)`，原点固定在场景 `imagineProfile.mapArea` 中心，X向东、Y向北，显示范围与场景边界一致。图例位于图内左下角，使用白色不透明背景，分别列出母巢、哨卫巢和暗巢。人族部署区依据场景 `redArea` 绘制，使用斜线纹路，中央标注“人族部署区域”。标题采用“E02：偏置新月”的形式。每张地图的母巢、哨卫巢、暗巢分别使用 `M00…`、`S00…`、`A00…` 编号，各类内部按实体ID排序、独立从00开始；`scenarios/map_labels.csv` 保存展示编号与实体ID的对应关系。

批量重绘正式20张图片并同步图片校验值：

```bash
python -m pip install 'matplotlib>=3.8,<4'
python -m scenarios.cases.plot_maps --latin-font /path/to/times.ttf --font /path/to/simsun.ttc
```

系统已安装对应字体时，可省略字体路径参数。中文也可使用开源宋体 `FandolSong-Regular.otf`。

实体位置统一使用 `pos={x,y,z}`，x向东、y向北、z为高度，单位为米；速度为 `vel`，单位为米/秒。图中圆表示哨卫20公里三维探测范围的水平投影。母巢和哨卫巢的开局目录公开初始位置及初始血量，暗巢需要通过合法探测获知。完整想定和组织方图片供环境与评测使用，选手训练资料按公开地图清单提供。

`reward.py` 按完整摧毁计分：从场景实体中读取母巢 `9400`、哨卫巢 `9600`、暗巢 `9500` 及其初始血量，固定权重分别为5、2、1。正式地图的三类目标初始血量分别为24、12、2。血量小于或等于零的目标获得其权重，存活目标得零分；总分为100乘以已摧毁权重占全部计分目标权重的比例。简单、中等、困难地图的总权重分别为44、69、100。`K`与`raw_score`记录该占比，`T`恒为零。在 `config.yaml` 的 `scenario` 中填写场景 JSON 路径后运行：

```powershell
python main.py --config config.yaml
```

统一生成22个场景并更新JSON哈希：`python -m scenarios.generate`；加 `--redraw` 同步重绘20张正式地图。转换保留原布局比例、实体ID、血量和父子拓扑，重复执行不会改变坐标尺度。
