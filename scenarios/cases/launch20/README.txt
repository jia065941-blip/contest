连续自由部署与立即出发20图

版本：2026年11月13日，减量红方、原蓝方配置
布局：local_xyz_m_20261103
正式地图共20张，默认加载E01。
想定省略运行时通信字段commRangeInfo，由Entity加载时初始化为空字典；文件哈希以当前manifest.json为准。

一、文件
scenarios下E01至E06、M01至M06、H01至H08各自包含同名JSON和images下同名PNG：
同名JSON：模型配置、地图与部署区域、实体初态和时钟；metadata保存地图编号、标题、难度和说明。
同名PNG：人族部署区域、虫巢分布、分类编号和哨卫20公里感知范围的水平投影，供场景设计与评估使用，包含暗巢位置。
scenarios目录中的map_labels.csv保存图片编号与原始实体ID的对应关系。母巢、哨卫巢、暗巢分别以M、S、A为前缀，每张地图的各类编号独立从00开始。
scenarios目录中的manifest.json保存20图索引及发布文件的SHA256。自定义地图直接按JSON路径加载，无需登记清单或维护哈希。

二、设计
简单档母巢、哨卫巢、暗巢数量为4、7、10；中等档为6、12、15；困难档为8、20、20。
简单、中等、困难档分别包含6、6、8张地图；毁灭者、突击者、清道夫数量分别为15/24/85、24/37/128、40/66/214。
红方共同使用连续矩形，自主选择每个单位初始位置；简单、中等、困难档的东西宽度分别为40、50、60公里。部署高度3000米，部署完成后全部出发，通过位置与路程形成到达先后。
简单、中等、困难档的自爆虫总量分别为78、146、348只；毁灭者与突击者合计分别为39、61、106个，对应比例约2.000、2.393、3.283。各虫巢库存保持原配置。
M06由两个关键哨卫巢构成前方入口，后方母巢与入口东西间距约38公里，邻近两个暗巢提供搜索任务。H03具有错位入口，后方母巢与入口东西间距约44公里，南北错位4公里，三个暗巢分布在通道两侧。每张地图的完整布局以同名JSON为准。
母巢、哨卫巢、暗巢的初始血量分别为24、12、2；视野塔数量按三档分别为7、12、20。哨卫巢按20公里三维距离探测存活、可见且公开stage>=2的红方，公开巡航阶段2对应原生阶段3，图中圆形为范围的水平投影。
天眼实体数量及引擎使用上限按小、中、大图分别为2、3、4，每次持续80步；当前R7空间策略按计划启用一次。对局时限为3000步，每个仿真步骤对应1000毫秒。

三、加载
仓库根目录执行：
python main.py --config config.yaml
在config.yaml中设置scenario为所需场景JSON路径，例如scenarios/E01.json。render_mode设为human可打开界面。

四、计分与实验接口
只有血量小于或等于零的目标获得分数。母巢、哨卫巢、暗巢权重分别为5、2、1；得分为100乘以已摧毁目标权重之和，再除以全部计分目标权重之和。存活目标得零分，摧毁时间不影响得分。
简单、中等、困难档的计分总权重分别为44、69、100。地图难度和策略表现以本版本地图及当前策略接口的真实测试为准。
连续部署、全部立即出发和天眼次数要求，需要由运行程序及赛题校验共同执行。地图文件自身不承担动作校验。
红方策略读取公开的母巢、哨卫巢初始位置及初始血量、己方单位和合法探测信息；完整场景及布局图中的暗巢坐标供组织方评估使用。选手训练文件按公开地图清单提供。

坐标统一使用pos={x,y,z}，x向东、y向北、z为高度，单位为米；vel为米/秒。mapArea使用xMin/xMax/yMin/yMax，部署顶点使用[x,y]。运行python -m scenarios.generate校验并生成全部22个场景，加--redraw重绘正式20图。
