# 红方基线

本目录保存红方可运行策略及其共享信息契约。当前的 R0--R3 是稳定对照基线；后续策略从 R4 开始新增，不修改它们的定义或默认参数。

## 共同信息边界

所有 R0--R3 在开局使用 core 的 `TrainingEnv._get_init_ship_observation()`。尽管函数名中有 `ship`，它返回的是完整的初始可用目标目录：

- `9400`：固定目标；
- `9500`：无人船；
- `9600`：拦截阵地。

每条目录项包含 ID、真实初始经纬高、血量、类型、阵营、初始探测和通信字段。策略通过 `priors.initial_targets_from_observation()` 将其转换为 `TargetPrior`；不再做类型过滤。策略还可读取每个红方平台自身报告的位置、类型、存活状态与已发射状态，但不读取 `TrainingEnv._get_observation()` 的全局态势。

当前场景中 `9500` 没有运动逻辑，初始坐标即整局真实坐标。R0--R3 尚未融合后续探测或毁伤确认：目标目录在单局中保持静态。

## R0--R3

| 基线 | 名称 | 分配方式 | 适用作用 |
|---|---|---|---|
| R0 | `r0_random` | 对完整初始目录做可复现随机分配 | 零知识偏好的随机对照 |
| R1 | `r1_priority` | 按目标价值、距离、已覆盖数量和平台—目标基础命中能力逐个平台贪心选择 | 能力匹配的规则对照 |
| R2 | `r2_static_assignment` | 开局一次性生成固定分配；小规模精确求解，大规模确定性贪心 | 静态全局分配对照 |
| R3 | `r3_rolling_rules` | 每 20 步重新分配尚未发射的平台，每次最多释放其 25% | 仅按平台状态滚动的波次对照 |

共同发射时序为 H/M/L 分别延后 0/10/20 步。R1--R3 的能力项来自 core 当前的基础命中率：H/M 优先 `9400/9600`，L 优先 `9500`。R0 不施加该偏好，保留纯随机特性。

## 新增 R4+

R4 及以后可在不改动 R0--R3 的前提下扩展。建议顺序：

1. 先增加独立的航迹融合组件：初始 `TargetPrior` 作为先验，后续仅融合己方已接收的 `detectInfo` 和可获得的毁伤确认；
2. 再增加搜索、重新定位、目标失效和再分配逻辑；
3. 最后实现多波次组成、平台编组、时间间隔、侦察/牵制等组合策略。

新增策略应实现 `build_red_baseline()` 对应的决策接口，并补充 `tests/test_red_baselines.py`；禁止直接读取全局环境实体表。
