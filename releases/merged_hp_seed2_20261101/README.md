# 合并收益树 + HP：seed2 二十图发布

本目录发布 2026-11-01 同内存评估中最高分的实际策略 `merged_hp`，历史二十图等权平均 **99.4277997365**。
它包含冻结 DeepSeek 开局选择、V00–V11（文件中别名 A00–A11）方案、V12-R3 躲避模型、`mission_v12`、
`prior_t03_make`、A/B 的提议与执行代码、合并收益树，以及 HP 执行树。
本版本合并树实际只输出 KEEP/A；保留 B 角色的绑定与特征计算，因为这是获胜树的输入依赖。
不包含 Astra 在线 skill 选择器、broker、选择请求或外部模型调用入口。

## 复现的范围

本包独立于 `python-machine-learning`、其他 contest 分支、本机缓存和模型 API 密钥。
SDK、240 份固定候选计划、V12-R3 权重、共享推理代码、参考 CPython 构建和原实验实际使用的 Python 依赖均在 Git 中。
依赖以 40 MiB 分片保存并逐文件校验，安装不需要联网下载包；系统仍需 Linux x86_64、C 编译器、兼容的 glibc/C++ 动态库和可执行 tmpfs。
安装检查遇到缺失依赖、原生 ABI 或校验问题会停止，不会静默换模型或运行环境。

**不能承诺另一服务器恰好得到 99.4278。** 官方同时间事件的排序依赖
`id(simulator.entity_ext.entity)` 和 `id(simulator)`，新进程的内存布局可以改变后续结果。
本包不修改这一规则，也不以历史分数替代新结果。源码、权重、方案和规则可核验重现；
逐分重现还受原生地址顺序影响。原实验内存快照不等于能跨机器恢复的进程镜像。

发布评估入口比较同一合并树 **HP 关闭/开启** 的两条同内存分支，
从 HP 首次将产生不同动作前 fork；根进程执行关闭 HP 的对照，子进程执行获胜策略。
若始终没有动作差异，则只有一条实际轨迹，并明确标记命令等价。
这与历史四策略实验采用同一策略逻辑，但删掉了 Astra 分支及其更早可能触发的分叉；
**不能把这个两分支新启动入口称作原四分支进程的字节级重放。**
保留对照仅为在新机器测量 HP 效应；不会发布其他 skill 选择器。

## 安装和无对局验证

从仓库根目录执行：

```bash
cd releases/merged_hp_seed2_20261101
python3 install.py
```

`install.py` 在 `.python/` 解包原 CPython 3.11.17 构建，在 `.venv/` 创建虚拟环境，
解包随附的冻结依赖，核验所有资源，编译并加载 deepcopy 扩展，加载 V12-R3 权重，
最后重放随包的**已保存合法观察**核对树决策。安装不会启动仿真、调用模型或训练。
整个安装流程不需要模型或 Python 包网络请求；本包不含 API 凭据。
`requirements.lock` 用于核对实际依赖版本；包源未必仍提供所有原实验版本，故不依赖重新解析下载。

已有相同参考解释器与依赖时也可直接执行：

```bash
/path/to/python -B bootstrap.py
/path/to/python -B verify_release.py
```

`bootstrap.py` 要求 `sys.version` 与 `environment_reference.json` 的参考构建一致；
使用随包解释器可避免手工编译的版本字符串或 ABI 差异。必须保留共享 `libpython3.11`。
`/dev/shm` 应挂载为**允许执行**的 tmpfs，并关闭 swap；容器默认 `noexec` 时应由服务器管理员配置。
`verify_release.py` 检查二十图全部获胜轨迹的 HP 逐步决策、原生指令回执、
合并树的合法特征/绑定/选择及二十份实际开局计划重建；不会计算新的仿真成绩。
这些属于移植一致性检查，不能代替新服务器的完整原生评估。

只检查评估输入及资源能力，不启动对局：

```bash
.venv/bin/python -B evaluate.py --prepare-only \
  --out outputs/seed2_01 --ram /dev/shm/merged_hp_seed2_01 --workers 64
```

## 在目标服务器执行完整评估

```bash
.venv/bin/python -B evaluate.py \
  --out outputs/seed2_01 \
  --ram /dev/shm/merged_hp_seed2_01 \
  --workers 64
```

建议用 tmux/systemd 托管长任务。不要重复启动相同输出目录。
固定 seed2、二十图、3000 步上限、蓝方 `b0_fixed_ratio_random`、拦截比例 2。
保留 15 秒检查网格、900 秒技能提议截止和战略技能最多使用一次。
`--workers 64` 指**所有原生根进程和 fork 后代合计上限**，不是 64 个根进程再各自分叉。
实际并发还受 CPU affinity/cgroup、其他原生任务和 90% 内存上限约束。
每个 E/M/H 根预留两个分支的 8/18/46 GiB；当任务数或资源不足时不会为凑满 CPU 超额启动。
资源租约采用 `/tmp/launch20-native-host-leases-v1`，保留已释放的租约作为审计记录。

输入通过封闭 memfd 提供。分叉恢复 Python/NumPy/Torch RNG，逐步检查两种地址注册表，
隔离输出并验证原生结束、HP 回执和官方 5/2/1 计分。历史二十图 baseline/baseline
及非对称分配压力负对照证据随包保留；不自动增加新负对照或重试。
它们是原宿主已完成的负对照，不应称为新服务器已经重新通过负对照。
模型只看到合法自身/群组观察；地址和内部物理摘要只用于评估。

结束后查看：

```text
outputs/seed2_01/summary.json   17 / M06 / E05,H04 / 全部请求地图分组统计
outputs/seed2_01/returns.csv    每图实际得分及同内存 HP 差值
outputs/seed2_01/archives/      逐图回报、合法轨迹、回执、地址/RNG 和失败分析所需证据
outputs/seed2_01/protocol.json  发布文件指纹、种子、CPU/RAM 和负对照来源
```

输出目录必须不存在；不自动续跑、重试或择优覆盖。失败会归档已有失败证据并保留 tmpfs 原始文件，
不会把缺失地图算入完整均值。停止控制器会终止本轮原生进程组；重新运行必须明确使用新的目录，
并把重复运行与首次结果分开报告。宿主若强杀控制器，应先检查其原生进程是否仍在运行。

HP 的 H 行为是在冻结合法条件下清零末端垂向机动；M 行为是根据自身过期轨迹发出受约束的归向航点。
整体得分提升不证明 H/M 都必需或存在不可分解合作。部分改善只有 H 特殊行为实际执行。

历史外层控制器中断过，宿主资源监控缺口约 577.85 秒；原生进程保留原内存并继续，无地图重跑。
