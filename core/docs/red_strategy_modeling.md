# 红方全局规则与多基线策略：形式化建模与评审稿

**状态：基线策略核心包、独立测试和场景初始态势合同测试已完成；引擎步进联调使用具备完整项目依赖的 Python 运行环境。**

## 摘要

本项目当前红方策略由单枚导弹独立、随机地选择初始目标和机动时机组成；场景中的 `rules` 为空，训练奖励主要是存活奖励。这使得“目标覆盖、波次协同、资源节约和任务效果”无法被统一表达，也无法可靠比较不同策略的收益。

本文先将红方任务抽象为：在有限时域内，为异构导弹选择**部署位置、发射时机、目标、机动和卫星使用时机**，以最大化目标毁伤/突防效果，并同时满足区域、发射、资源和信息可得性约束。本阶段基线采用固定的策略结构、参数、信息输入和随机种子，并给出四个可直接比较的方案：

1. B0：可复现随机策略——真实性能下限；
2. B1：固定优先级全局规则——最小的协同规则基线；
3. B2：一次性全局整数分配——静态优化基线；
4. B3：滚动时域、离线调参的全局规则——强规则/优化基线。

任何部署前，执行“信息边界、物理约束、基线可复现性、收益显著性”四项评审；评审结果形成部署输入。

## 1. 决策问题与边界

### 1.1 实体、时间与状态

离散仿真时刻记为 \(t=0,\ldots,H\)。设：

- \(\mathcal M\)：红方导弹/飞行器集合，按类型 \(k(m)\in\{H,M,L\}\) 区分高、中、低性能平台；
- \(\mathcal T\)：任务目标集合；\(v_j\ge0\) 为目标 \(j\) 的任务价值；
- \(\mathcal D\)：红方可部署区域；\(\mathcal D_H\subseteq\mathcal D\) 为高性能平台适用区域；
- \(b_t\)：剩余卫星使用预算；\(c_{m,t}\in\{0,1\}\)：平台是否已发射/失效；
- \(x_{m,t}=(lon,lat,alt,vel)\)：平台状态；\(h_{j,t}\)：目标健康状态。

全局真实状态写为

\[
s_t=\{x_{m,t},c_{m,t}\}_{m\in\mathcal M}\cup\{h_{j,t}\}_{j\in\mathcal T}\cup\{b_t,t\}.
\]

本阶段观测 \(o_t\) 由“初始目标表 + 红方实时态势”组成。当前代码向每枚红方导弹提供自身状态，并在初始化时提供符合筛选条件的蓝方静态信息。后续接入探测链路后，可将经过规则确认的蓝方动态信息加入 \(o_t\)。

### 1.2 动作与硬约束

对每枚平台，动作记为

\[
a_{m,t}=(d_m,\ell_{m,t},y_{m,j,t},u_{m,t},q_{m,t}),
\]

其中 \(d_m\) 是初始部署点，\(\ell\) 为是否发射，\(y\) 为目标分配，\(u\) 为侧向加速度/改目标动作，\(q\) 为卫星使用动作。需满足：

\[
d_m\in\mathcal D_{k(m)},\quad \sum_j y_{m,j,t}=\ell_{m,t},\quad
\sum_t \ell_{m,t}\le1,
\]

\[
\sum_{m\in\mathcal M}q_{m,t}\le b_t,\quad
\sum_m y_{m,j,t}\le C_j,\quad |u_{m,t}|\le u^{max}_{k(m)}.
\]

其中 \(C_j\) 是单个目标允许同时投入的最大导弹数，用于控制目标饱和度。部署点采用多边形内判定，并满足最小间隔 \(dist(d_m,d_n)\ge\delta\)。

### 1.3 统一评估指标

一局的主效用定义为

\[
J=\sum_{j\in\mathcal T}v_j\,(1-h_{j,H}/h_{j,0})
+\lambda_b N_{breakout}
-\lambda_l N_{loss}
-\lambda_s N_{sat}
-\lambda_r N_{redundant}.
\]

指标按优先级报告：任务完成率、加权目标毁伤、突防数、任务耗时、损失数、卫星消耗和目标覆盖率。

## 2. 基线的判定标准

本文件中的 B0--B3 采用以下统一设定：

1. 在每组评测开始前登记代码版本与参数 \(\theta\)，在该组评测内保持一致；
2. 输入仅为第 1.1 节定义的合法观测；
3. 每一个动作均可由固定规则或确定性求解器复现；
4. 优化器若被使用，其目标函数、约束、求解时限和随机种子固定；
5. 在线输入字段与第 1.1 节的观测定义一致。

## 3. 四个冻结、可部署的基线

### B0：可复现随机策略（性能下限）

在合法区域内以固定随机种子部署；每枚导弹从初始目标表中等概率选择一个目标；使用固定的发射延迟和机动模板。令 \(\xi\) 为预先登记的种子，则

\[
a_{m,t}=f_{random}(o_t;\xi,m,t).
\]

它提供性能下限，用于量化全局规则和优化带来的增益。B0 同样采用区域、发射一次、卫星预算和动作边界等硬约束。

### B1：固定优先级全局规则（最小协同基线）

全局协调器按固定次序遍历“平台--目标”对，对每对计算一个可解释评分：

\[
S_{mj}=w_v\tilde v_j-w_d\tilde d_{mj}-w_c n_j-w_k cost_{k(m)}.
\]

\(\tilde v_j\) 是归一化目标价值，\(\tilde d_{mj}\) 是初始距离或可达时间，\(n_j\) 是已分配给目标 \(j\) 的数量。按 \(S_{mj}\) 从高到低贪心分配，若 \(n_j=C_j\) 则跳过该目标；同一型号使用预设的发射波次和机动模板。

\[
y_{m,j^*}=1,\qquad j^*=\arg\max_{j:n_j<C_j}S_{mj}.
\]

这是真正的“全局规则”基线：它有目标去冲突和共享预算，但没有运行时优化。权重、目标容量、波次表和部署槽位均固定在配置文件中。

### B2：一次性全局整数分配（静态优化基线）

仿真开始前，仅用初始目标表和红方初始部署槽位，一次性求解平台、目标和波次的分配；之后不重规划。令 \(z_{mjt}\in\{0,1\}\) 表示平台 \(m\) 在预设波次 \(t\) 攻击目标 \(j\)，\(p_{mjt}\) 是固定的型号/距离成功率查表值。求解：

\[
\max_z \sum_{m,j,t}v_jp_{mjt}z_{mjt}
-\alpha\sum_{m,j,t}cost_{k(m)}z_{mjt}
-\beta\sum_{j,t}overload_{jt}.
\]

约束为

\[
\sum_{j,t}z_{mjt}\le1,\qquad
\sum_mz_{mjt}\le C_j,\qquad
\sum_{m,j}q_{m,t}\le b_t.
\]

这是一条**静态、可重复的优化基线**：求解器、时限、最优间隙和输入表均固定。评测报告记录其相对 B1 的任务收益、资源消耗与求解时间。

### B3：滚动时域参数化规则（强规则/优化基线）

在线策略沿用 B1 的透明规则形式，并每 \(\Delta\) 步根据红方状态重新计算目标容量、待发射数量和波次。规则参数记为

\[
\theta=(w_v,w_d,w_c,C_j,\Delta,\delta,\text{wave table},\text{satellite thresholds}).
\]

在部署前，用固定训练场景集 \(\Omega_{train}\) 对 \(\theta\) 做网格搜索或贝叶斯优化；部署时冻结 \(\theta^*\)：

\[
\theta^*=\arg\max_{\theta\in\Theta}
\frac{1}{|\Omega_{train}|}\sum_{\omega\in\Omega_{train}}J(\theta,\omega)
-\eta\,\mathrm{CVaR}_{\alpha}[-J(\theta,\omega)].
\]

评测必须在未参与调参的 \(\Omega_{test}\) 上进行。B3 的“优化”只发生在离线参数选择阶段，在线策略仍是固定的规则函数；因此它仍是合理、但更强的基线。

## 4. 统一评测协议

| 基线 | 是否全局协调 | 是否在线重规划 | 是否离线优化 | 评测中的可变部分 |
|---|---:|---:|---:|---|
| B0：可复现随机 | 否 | 否 | 否 | 仅预登记随机种子 |
| B1：固定优先级规则 | 是 | 否 | 否 | 无 |
| B2：一次性整数分配 | 是 | 否 | 是（单局起始） | 无 |
| B3：滚动参数化规则 | 是 | 是（规则重算） | 是（仅评测前） | 合法红方观测 |

所有基线必须使用同一场景集、同一随机种子集、同一最大步数及同一硬约束。建议至少报告 30 个种子；以 B0 为配对对照，报告均值差、置信区间和失败案例，而非只报告最佳单局。B3 的离线调参场景与最终测试场景必须严格分离。

## 5. 扩展建模方向

- **CMDP**：以 \(\mathcal M=(\mathcal S,\mathcal A,P,r,\gamma,\mathcal C)\) 表示受约束决策过程；奖励可由毁伤增量、突防增量、损失、卫星消耗和重复分配构成。
- **Dec-POMDP / CTDE**：以局部历史 \(\tau_{m,t}\) 和全局广播字段 \(g_t\) 表示多平台协同决策；训练阶段使用联合价值函数 \(Q(s_t,\mathbf a_t)\)。
- **鲁棒场景优化**：在场景集合 \(\Omega\) 上采用 \(\mathbb E[J]-\eta\,\mathrm{CVaR}_{\alpha}[-J]\) 选择参数，描述不同拦截强度、时延和信息质量下的任务表现。

## 6. 基线模型评审与确认清单

在写任何部署代码前，请确认以下事项：

1. **任务目标**：目标价值 \(v_j\) 如何定义？是毁伤全部目标、优先关键节点，还是最大化突防数量？
2. **信息边界**：红方是否只可使用初始化蓝方信息，还是可使用由探测/卫星事件合法获得的实时信息？
3. **物理含义**：`SET_DESIRED_ACC_Z` 的输入范围、作用时长，以及不同型号的实际速度/机动上限是否以引擎为准？
4. **卫星规则**：预算是全局共享还是单平台独立？使用后会获得何种信息或效果、持续多久？
5. **成功判定**：从引擎事件或最终状态中，如何唯一识别“发射、拦截、突防、命中、目标毁伤”？
6. **允许的集中协调**：是否允许红方平台共享自身状态并接受全局调度？若允许，广播字段应固定且可审计。

评审通过条件：上述六项有明确答案；动作都能映射到现有 `CommandConverter` 支持的四类指令；每条约束都能在日志中检查；B0 在固定种子下逐次运行结果一致；B3 的调参场景与测试场景已隔离。

## 7. 部署顺序

1. 修复单弹状态重置、固定随机种子，并补齐事件指标，建立 B0；
2. 实现只包含合法红方信息的全局状态板、固定评分和目标容量，形成 B1；
3. 固定部署槽位与波次表，求解一次性整数分配，形成 B2；
4. 在独立调参场景集上冻结 B3 的规则参数，并只在留出测试集评测；
5. 汇总 B0--B3 的任务收益、资源消耗、约束合规率和失败案例，形成阶段评测报告。

### 8.3 接口边界

`adapter.py` 是唯一的环境接入位置，负责三类转换：

1. `TrainingEnv` 观测字典 → `RedObservation`；
2. `BaselineDecision` → 当前 `CommandConverter` 接受的动作数组；
3. 引擎状态/事件 → 评测指标。

策略、优化和评测模块仅依赖 `domain.py` 中的数据结构。这样每个基线都能在离线单元测试、独立运行脚本和环境仿真三种模式下复用。
